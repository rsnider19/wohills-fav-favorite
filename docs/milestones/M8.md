## Goal

Make the lights site launch-ready with everything that can be done locally, and hand the user
a written checklist for everything that can't:

- **Share card and social meta**: a 1200×630 `og:image` in the site's own look, with
  `summary_large_image` and alt text.
- **Playwright smoke tests for both apps in CI**: a GitHub Actions workflow that checks every
  pull request against a throwaway local Supabase stack on the runner, with no secrets and no
  deploys, a one-minute `@smoke` subset, and the Vercel preview still the deploy signal.
- **An accessibility pass**: axe (WCAG 2.2 A/AA + best practices) on every lights screen,
  phone and desktop, with zero violations; the parade's known findings recorded and pinned.
- **The runbook** (`docs/runbook-lights.md`): the hosted rollout, the hosted rehearsal and the
  safe wipe as an operator checklist **for the user** (the agents are not allowed to touch
  hosted services), the `contest-admin` commands for running the contest, emergencies, and a
  record of the local rehearsal.
- **Follow-ups from earlier reviews**: the flaky 44 px map test, the "Vote cast" flash in the
  first second after load, and core's `useResults` reading an error as "no results".
- **Done when** (changed from the plan, D1): the runbook has been rehearsed end to end
  against the **local** stack, including the wipe, with the parade data untouched; every AC
  below passes. The hosted rehearsal is Part B of the runbook, run by the user before Nov 28.
